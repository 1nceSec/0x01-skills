# 自动交接 Skill v1.0

> 结构化记忆 > 反复压缩。写下来的不会衰减，转述的每次都丢。

## 触发条件

1. **用户主动触发**：说"交接"、"handoff"、"写交接文档"
2. **PreCompact hook**：auto-compact 前 hook 确定性注入 `[AUTO-HANDOFF]` 到 AI 上下文
3. **全局规则触发（CLAUDE.md §3）**：工具计数 hook 达到阈值时自动触发，不限于skill模式
4. **Skill内部触发**：core-pentest-flow/web-vuln-hunting等skill的轮次检查点触发

## 交接流程

### Step 1: 收集当前状态

从当前会话中提取以下信息：

```
1. 任务目标：用户最初要做什么
2. 已完成：哪些任务/步骤已经做完，结果是什么
3. 进行中：当前正在做什么，做到哪一步了
4. 关键发现：重要的发现、决策、结论（含文件路径和行号）
5. 文件变更：本次会话修改/创建了哪些文件
6. 失败记录：尝试过但失败的方案（避免新会话重蹈覆辙）
7. 待办事项：接下来要做什么，优先级排序
8. 环境上下文：当前工作目录、分支、依赖版本等
```

### Step 2: 写入交接文档

**先确定主题名**：
- 用户手动触发时：问用户主题名
- 自动触发时：自动生成，不打断流程

**文件路径**：`E:\Agent\Claude\handoff\{模式}\{目标}\handoff-{日期}-{HHMM}.md`

模式目录：
- `pentest` — 渗透测试
- `web-vuln-hunting` — 漏洞挖掘/SRC
- `red-team` — 红队评估/攻防演练
- `other` — 其他（代码审计、调研等）

目标目录：用域名或简短标识，如 `example.com`、`内部OA`、`api-gateway`

示例：`E:\Agent\Claude\handoff\web-vuln-hunting\example.com\handoff-20260930-1423.md`
**自动概括当前任务目标**：从会话上下文中提炼一句话描述本次会话的核心任务/目标，写进文档头部。
每次新增文件，不覆盖——compact后上下文已压缩，覆盖会丢掉前次记录的细节。

文档格式：

```markdown
# handoff-{目标}-{日期}-{HHMM}
> **任务目标**: {从会话中概括的一句话核心目标}

生成时间: {timestamp}
工作目录: {cwd}

## 已完成
- [x] {任务1} — {结果/产出}
- [x] {任务2} — {结果/产出}

## 进行中
- [ ] {当前任务} — 做到了{哪一步}，下一步是{什么}

## 关键发现
- {发现1}（{文件路径}:{行号}）
- {发现2}

## 文件变更
- {文件路径} — {做了什么改动}

## 失败记录（新会话避免重复）
- {方案X} 不行，因为 {原因}

## 待办事项（按优先级）
1. {最重要的下一步}
2. {次要任务}

## 环境上下文
- 分支: {branch}
- 关键配置: {config}
- 注意事项: {caveats}

## 浏览器状态
{调用 browser_tabs 获取当前打开的页面URL列表，如果playwright未运行则写"无"}
- {tab1_url} — {页面描述}
- {tab2_url} — {页面描述}
```

### Step 3: 提醒用户

交接文档写完后，输出：

```
交接文档已写入 E:\Agent\Claude\handoff\{模式}\{目标}\handoff-{日期}-{HHMM}.md

建议现在切换到新会话，然后告诉我：
"读取 E:\Agent\Claude\handoff\{模式}\{目标}\handoff-{日期}-{HHMM}.md"
```

## 规则

1. **只写事实，不写推测**。已确认的写"已完成"，未确认的写"进行中"或"待验证"
2. **文件路径必须是绝对路径**。新会话没有上下文，相对路径无意义
3. **失败记录必须写清原因**。不写"方案A失败"，写"方案A失败因为X，下次应该Y"
4. **不写敏感信息**。API Key、密码、Token 只写管理方式（如"在 .env 中"），不写值
5. **交接文档新增写**。每次触发生成新文件（文件名含HHMM时间戳），不覆盖旧文件——compact后上下文已压缩，覆盖会丢细节
6. **渗透测试场景增强**：如果当前是渗透测试，额外收集：
   - 已发现漏洞（类型/端点/严重性/PoC状态）
   - 攻击面地图（已探测接口清单）
   - 请求头基线（Cookie/Token/UA 等，脱敏后保留结构）
   - 当前测试阶段（Phase 1-5 的哪个阶段）

## 新会话恢复

新会话开始时，读取 `E:\Agent\Claude\handoff\{模式}\{目标}\` 目录下最新的交接文档：
- 确认任务目标是否仍然正确
- 检查文件变更是否仍然存在（`git status` 验证）
- 从"进行中"和"待办事项"继续
- 跳过"失败记录"中已标记的死路
- **恢复浏览器状态**：如果交接文档有"浏览器状态"段且列出了URL，用 `browser_navigate` 逐个打开
