# 安全红线(Safety Boundaries)

> 本文件是渗透测试的"护栏"。红线动作**一律禁止**,无论看起来多么有诱惑力。授权范围 + 红线 = 可执行边界。

---

## 1. 授权前提(先决条件)

- **仅在已获书面授权的目标上执行**(授权书 / SOW / 测试委托 / 靶场说明)。
- 每次启动前确认 **scope 白名单**:授权的域名 / IP / 端口 / API。
- 明确 **Out of Scope**:禁止触碰的资产、系统、数据。
- 靶场/CTF 场景按赛题说明界定 scope;商业测试按合同界定。
- **未确认授权时**:只允许被动信息收集(OSINT、公开数据),不发送任何主动测试请求。

---

## 2. 数据安全红线

| 动作 | 允许 | 禁止 |
|------|------|------|
| SQL 注入 | 识别数据库版本 / 当前库名(`version()`/`@@version`/`database()`)、判断注入点是否存在 | 读取表名 / 列名 / **任何业务数据**;`INTO OUTFILE` 写文件 |
| 数据增删改 | 仅**报错注入**或**无回显存在性判断**(布尔/时间),不产生真实数据变更 | `DROP` / `DELETE` / `TRUNCATE` / `UPDATE` / `INSERT` 真实数据 |
| 增删改接口 | 仅测是否可注入(报错/盲注),不构造会改写数据的 payload | 真实创建/修改/删除任何业务记录 |

> 原始草稿中"SQLi 最多跑到 database()"的措辞改为:**仅识别到「数据库版本/库名」层级即止,禁止继续读取表、列、数据**。

---

## 3. 命令执行红线(RCE)

| 动作 | 允许 | 禁止 |
|------|------|------|
| 回显验证 | `whoami` / `hostname` / `id` / `uname -a` 等只读命令,用于确认漏洞存在 | 反弹 shell(reverse shell) |
| | | 权限提升(提权) |
| | | 持久化(计划任务/启动项/后门账号) |
| | | 写入 webshell / 落地工具 |
| | | 读取/外带敏感文件(`/etc/shadow`、密钥等) |

---

## 4. 带外数据(OOB)红线

- **禁止用 OOB 外带任何业务数据**。
- dnslog / collaborator 类带外通道 / 自建回调**仅限自有可控基础设施**,且只用于**漏洞存在性验证**(如带出一个随机无意义字符串),不承载真实数据。
- 禁止将目标数据通过任何通道回传到非授权地址。

---

## 5. 可用性红线

- **禁止 DoS / DDoS / 资源耗尽**( fork 炸弹、超大 payload 撑爆解析、海量并发)。
- 控制请求**频率与并发**,避免影响目标正常运行。
- 禁止爆破到**账户锁定**(锁定会破坏目标可用性并留下噪声)。
- 涉及批量请求的测试,优先在低峰期、控制速率。

---

## 6. 边界红线

- **不触碰 scope 外资产**:不扫描授权范围外的 IP/端口/域名。
- **不横向移动、不内网渗透**(超出授权 scope 的部分)。
- SSRF 仅允许回连治理规则指定的验证地址（`src-ssrf.bytedance.net/ssrf`）；**禁止**探测内网端口/服务、**禁止**访问云元数据（169.254.0.0/16 等网段）——以 `E:\Agent\0x00_Governance\AGENTS.md` 为权威。
- 发现 scope 外的严重问题 → **记录并报告,不主动测试**。

---

## 7. 报告与证据红线

- 证据保留**最小必要**:请求/响应片段足以证明即可,**不囤积真实业务数据**。
- 截图/导出涉及真实数据时脱敏。
- 测试产生的临时数据(如上传的测试文件)在测试结束后**清理**。

---

## 8. 红线冲突时的优先级

当"完成测试目标"与"红线"冲突时,**红线优先**。宁可漏报一个漏洞,也不越线造成不可逆损害。遇到红线限制无法深入的情况,在报告中明确标注"受红线限制未深入验证"。
