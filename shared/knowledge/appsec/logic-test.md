### 1.4 商家促销绑定：券挂到别人的货（短表有指针）

> 本质：商家后台「把我的促销/券绑到某件货」只信请求里的 `productId`，不查这件货是不是本店的。  
> 和结账改价、改券面值、结账换便宜 SKU **不是一条**。短表一行指向本节。

**认：** 有商家/供应商后台；能建满减、无门槛券、促销；绑货接口名常带 `relate` / `bind` / `attach` / `apply` + `promo` / `salespromotion` / `coupon`；body 里同时有券/活动 ID 和 `productId` / `skuId` / `goodsId`。

**打：**

1. 用本店号建一张规则狠的券（无门槛、面值够大、不限本店品类更好）  
2. 正常绑一次自己的货，抓住绑定请求  
3. **只改** `productId`（或同义字段）成别人店、别的品类的货；券 ID / 活动 ID 不动  
4. 不登录打开 C 端那件货的详情/下单页，看标价和应付  

**算成：** C 端别人那件货的应付价按你这张券掉下来（能下单更好）。只证明绑定接口 200、商家后台列表多了一行 → 不算，必须 C 端价真变。

**假点：** 绑定成功但 C 端价/结算不变；后端按商家会话重写商品、只绑得动自己的货；改的是 C 端结账包里的 `productId` 换成更便宜的 SKU（那是清单里已有的「结账换货」，不是本条）。

和邻近手法别混：

| 本条 | 别当成 |
|------|--------|
| B 端绑券接口，改的是「绑到哪件货」 | C 端结账改 `amount` / `coupon_amount` |
| 自己的券 + 别人的 `productId` | 结账把 `productId` 换成更便宜的 SKU 再付钱 |
| 要看到 C 端价掉下来 | 商家后台列表显示绑成功就算 |

开场半分钟：有商家后台就建券 → 抓绑定包 → 换一个明显不是本店的 `productId` → 打开 C 端看价。

## 六、验证码绕过手法全清单（来源：隐雾案例库，逐条带真实出货）

> 任意用户注册/登录/改密是一族漏洞，原理相通：**验证码与账号/手机号/邮箱未统一校验**。发现一处必联想其余两处。

| # | 手法 | 操作 | 判定 |
|---|------|------|------|
| 1 | 验证码复用（A码B用） | 账号A获取验证码B1，提交时把账号改成A2，验证码仍用B1 | 服务端只校验码对不对，不校验码属于谁 |
| 2 | 置空/布尔绕过 | `code=null` / `code=true` / `code=1` / 删参数 | 跳过校验逻辑 |
| 3 | 万能验证码 | `000000/123456/147258/888888`（开发后门） | 直接登录成功 |
| 4 | 验证码回显 | 返回包 JSON 里带 code/验证码字段 | 截图返回包+手机短信一致 |
| 5 | 双写 | `phone=138xxx&phone=139xxx` 同参数两名 | 两号同收码或其一通过 |
| 6 | 改返回包 | 登录返回 `{"success":false}` → 改 true；或 `userid:123`→`124`（小程序登录/第三方登录高发） | 前端只认返回包字段 |
| 7 | 改接收方 | A 的账号 + 验证码发到自己手机/邮箱（改 sendCode 的 phone/email 参数，验证时用 A 账号+自己收到的码） | 用户名/手机号/验证码三者未绑定 |
| 8 | 跳步骤 | 记录改密流程 step=a→d 的 URL，直接请求 `?step=d`（设置新密码页） | 服务端不校验前置步骤完成态 |
| 9 | 改数据特征 | 验证通过后抓返回包/隐藏域中的 `code_id/userid`，把他人的特征值替换进自己的提交 | 步骤间靠前端传递身份 |
| 10 | 4/6位爆破 | 4位必爆（<1万次）；6位看限频——无限制或时效>5min可试（部分SRC/众测收） | 见 race-condition §2.6；控制线程避免锁号 |
| 11 | 逗号/加号绕过 | `mobile=138,` / `mobile=+86138xxx` / `%0a`等不可见字符追加 | 短信轰炸限频绕过（响应差异判断是否发出） |

**经验**：发现 4 位验证码 = 看到钱；一个功能点拿到验证码漏洞后，把"登录/注册/改密/换绑/任意申请"全部过一遍，通常不止一个。

## 八、支付细节补充（在 §一 之上）

1. **四舍五入精度**：充值 0.19 付 0.019 → 实际到账 0.02。构造比最小单位多一位的小数。
2. **重复扫码**：首单优惠二维码保存（截图/抓包）后重复扫码；或双手机同时扫码同时输密码。前提：二维码与支付成功未强绑定 / 支付后订单未使码失效。
3. **退款并发**：退款请求并发重放 → 一单多退（先小额自测）。
4. **支付状态伪造**：支付回调/查询接口返回包改 `status`（配合 §六.6）。
5. **对比法找关键参数**：两个用户/两次下单的包做 diff，不变的参数删掉试，变化的逐个改——先单参数再组合。

## 九、游戏/答题/抽奖/积分（结果参数重置类）

**共性**：客户端提交"结果"，服务端直接采信。

| 场景 | 手法 |
|------|------|
| 内置小游戏（投篮/闯关） | 结算接口改 `goalCount/score/level`（多个包没串联，汇总包说了算）；参数含义靠字母猜+删参试+变值猜 |
| 答题 | 返回包带 `answer+correctAnswer` → 直接抄正确答案；改 `correctAnswer` 再嫖一个洞 |
| 抽奖 | 每天N次 → 最后一次并发突破（race-condition §5.3）；返回包先出奖再扣次数 → 换 prizeId |
| 签到/积分 | 并发签到；`number:1`→`1000000` 刷赞/刷量 |
| 会员/付费内容解锁 | 观看次数扣减接口直接改次数参数（负数/大数）；免费次数从 3 改成负数 |
| 越权免费下载付费资源 | 付费资源在 OSS 有固定路径，历史包泄露 `ossId`/路径规律；先上传自己的文件看存储路径 → 拼他人路径 |

**答题类前置**：答题结果必须能换利益（积分/礼品/排行）才可报；泄露题目本身配合"可控制答题分数"一起报。

## 十、库存/订单业务破坏（证明即止，红线）

- **锁单占库存**：加购/下单不付款且无超时释放 → 全站用户无法购买。**证明**：锁一件观察他人购买失败提示即收，**禁止**批量锁全品类。
- **订单 id 越权**：订单详情 `orderID/orderId` 遍历看他人订单（收件人/地址/流水）——IDOR 最常见出口。
- **文件 id 唯一性**：发帖/上传返回 `fileAccessId`，发布时替换成他人 id → 偷他人图片作品 + 原图被强制删除（id 唯一且只归属一人）。发现"文件 ID 唯一"机制时主动试替换。

## 十二、匿名/打码数据反溯

- **匿名发言溯源**：匿名接口返回 `authorID` 类特征值 → 在其他接口（关注/点赞）找同值参数 → 关联出真实用户。**通用法**：数据包里找"特征识别参数"（手机号/身份证/userid/wxopen_id），跨接口匹配。
- **打码绕过**：列表打码 138\*\*\*\*，但"判断手机号是否存在"类接口的报错差异（"不是经办人"/"已注册"）可逐位 oracle 出完整号码。
- **弱口令联动**：身份证/学号当账号 + 身份证后 6 位当密码（谷歌语法 `site:edu.cn filetype:pdf "默认密码"` 找操作手册佐证）。
