# bucket-takeover

# 存储桶接管（Bucket Takeover）— 检测与定级 Playbook

> 与 `subdomain-takeover-test.md` 的关系：子域接管的**云存储变种**。子域接管要 CNAME 挂点；
> 桶接管**不依赖 DNS**——任何残留引用（JS/配置/CDN回源/App接口JSON）都算触发面。
> 一句话：**地址还在被引用，桶已经没了，名字谁都能抢。**
>
> **双视角**：SRC（vuln-hunting）视角 = 捡漏报配置错误（§4-§6，验证到"可抢注"即止）；
> killchain 视角 = 当**攻击向量**打（§9：抢注 → 可信域投恶意内容 → 初始访问/供应链加分）。

## 1. CORE CONCEPT

```
桶被删（项目下线/迁移/误删） → 桶名回流到"可注册"池（全局唯一、先到先得）
→ 系统里残留的引用仍指向该地址（JS写死/后端配置/DNS CNAME/CDN回源/接口JSON）
→ 攻击者用自己云账号抢注同名桶
→ 原系统所有打到该地址的请求，全落到攻击者控制的桶
```

本质 = 子域接管在云存储场景的变种（快递柜类比：搬走后柜号回收，快递单还写着旧柜号）。

## 2. 悬空引用的 5 种来源（触发面，逐处排查）

| # | 引用位置 | 排查方法 |
|---|---------|---------|
| 1 | 前端 JS 写死的桶 URL | F12 → Network / 源码搜云存储域名特征（§3） |
| 2 | 后端配置 / 环境变量 | 代码审计：grep 桶域名；.env/config 泄露时优先翻 |
| 3 | DNS CNAME 指向桶域名 | `dig CNAME sub.target.com +short` |
| 4 | CDN 回源配置指向桶 | 回源地址在 CDN 控制台，黑盒难见——看响应头/报错特征推断 |
| 5 | App 接口返回的 JSON 里带桶地址 | 抓包看接口回包里的资源 URL |

## 3. 云厂商域名指纹 + 未注册信号（认信号）

| 云厂商 | 桶域名特征 | 未注册回显（浏览器直访） |
|--------|-----------|------------------------|
| 阿里云 OSS | `xxx.oss-cn-xxx.aliyuncs.com` | NoSuchBucket / 404 带 Aliyun 错误码 |
| 腾讯云 COS | `xxx.cos.ap-xxx.myqcloud.com` | NoSuchBucket / "指定的桶不存在" |
| AWS S3 | `xxx.s3.amazonaws.com` / `xxx.s3-website-*.amazonaws.com` | NoSuchBucket (404) |
| 百度云 BOS | `xxx.bcebos.com` | NoSuchBucket / BOS 错误码 |
| 华为云 OBS | `xxx.obs.cn-north-4.myhuaweicloud.com` | NoSuchBucket / OBS 错误码 |
| 七牛 | `xxx.qiniucdn.com` / 自定义 CDN 域 | 404 / no such bucket |
| 又拍云 | `xxx.upaiyun.com` 系 | 404 / 又拍错误码 |

**四信号判据**（满足即高度可疑）：
1. 系统里存在指向云存储的地址（§3 域名特征，或自定义域 CNAME 到这些地址）
2. 桶当前未注册：直访回 NoSuchBucket / does not exist / 带云厂商错误码的 404
3. 系统仍在引用它（§2 五处任一）
4. 桶名可被外部注册（绝大多数云厂商：全局唯一、先到先得、删了即释放）

## 4. 发现路径（5 种，按省事排序）

1. **被动观察**：逛站时 F12 Network 收集云存储域名 → 直访看回显
2. **DNS 排查**：查子域 CNAME → 指桶域名而桶不存在 = 典型信号
3. **子域枚举 + 批量检测**：subfinder/amass → nuclei takeovers 模板 / dnsreaper 批量打"桶不存在"错误码
4. **代码/配置审计**：仓库、配置文件、CI/CD 流水线里 grep 硬编码桶地址，逐个验活
5. **公开情报**：HackerOne 已公开接管报告，学别人的发现路径

**核心动作就两步**：① 找到还在被引用的云存储地址；② 验证桶当前不存在且名字可注册。

## 5. 危害分级（写报告定级用）

危害取决于桶在原系统里"扛什么活"：

| 桶的用途 | 危害 | 定级倾向 |
|---------|------|---------|
| 加载 JS/CSS/下载包 | 内容劫持→偷 Cookie/token、钓鱼页冒充原站、带马安装包 | High（可至 Critical） |
| 系统仍在上传文件（证件/日志/备份） | 数据直接进攻击者桶 = 明文泄露 | Critical |
| 前端加载配置/规则文件 | 篡改业务逻辑 | High |
| 托管脚本绕过原域 CSP/信任链 | 供应链式打击 | High |
| 只放静态图片 | 危害有限；可 DoS（让桶回错误） | Medium/Low |

## 6. 验证流程（SRC 纪律）

```
1. curl 直访桶地址 → 确认 NoSuchBucket 类回显（存证）
2. 确认引用仍活着：找到至少一处仍在用的引用（JS/接口回包/CNAME）并截图
3. 【仅授权范围内】云控制台试注册同名桶 → 上传无害证明文件（POC ownership）
   ⚠️ 未授权目标禁止真抢注——报告写明"可抢注"证据（错误码+全局唯一机制）即可
4. 定级按 §5：看桶在原系统扛什么活
```

**SRC 写法提醒**：这是"配置错误"类，不是内存破坏类——报告要写清**引用链**（哪里引用→谁加载→加载什么），
审核员看不到引用链会当低危拒掉。CNAME 挂的桶接管同时可按子域接管报（引用面更直观）。

## 7. DEFENSE（给甲方的修复清单）

| Action | Priority |
|---|---|
| 别轻易删还在用的桶；删前全局搜一遍引用 | Critical |
| 删桶后清理所有引用：代码/配置/DNS CNAME/CDN回源 | Critical |
| 桶名加随机后缀，降低被猜中被抢注概率 | Medium |
| 用厂商"删除后保留桶名"能力（部分支持） | Medium |
| 定期监控自有域名/配置指向的桶地址验活 | High |
| 桶策略不开匿名写（即使被接管也限读写面） | High |

## 8. TRICK NOTES — 模型易漏点

1. **不是只有 CNAME**：最大挖矿面是 JS/接口回包里写死的桶 URL——DNS 层扫不出来，必须看流量和源码。
2. **404 ≠ 可接管**：必须匹配 NoSuchBucket 类**厂商错误码**；403（桶存在但私有）不是。
3. **自定义域蒙蔽**：CDN/自定义域在前，桶在后——追到底层回源地址再判。
4. **二阶悬空**：引用链 A 桶→B 桶→死桶，要跟到底。
5. **上传面优先**：仍在往死桶写数据的（上传接口没改）比只读静态的高一个量级。
6. **报告常见被拒理由**：只证明"桶可抢注"没证明"业务真在用"——引用链证据是命门。

## 9. RED-TEAM 用法（攻击向量视角）

> 红队语境下桶接管不是报告项，是**初始访问/供应链武器**：在目标可信域上拿内容投递权。

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | W1 侦察时收集目标 JS/接口回包里的云存储域名（§2 五处引用源） | 候选桶清单 |
| 2 | 逐个验活：NoSuchBucket = 悬空（§3） | 可抢注桶 |
| 3 | 【授权范围内】抢注同名桶 | 目标可信域上的内容控制权 |
| 4a | 目标页面仍加载该桶 JS → 投恶意脚本 | 受信域存储 XSS → Cookie/token 收割 |
| 4b | 桶承载下载包 → 换带马安装包 | 供应链打击（scoreboard: supply_chain bonus） |
| 4c | 桶承载配置/规则 → 篡改业务逻辑 | 业务控制权 |
| 5 | 目标仍往桶上传（证件/备份） | 数据面直接收割（无需利用） |

- 得分映射：投递成功 → `sensitive_data`/`supply_chain`；可信域钓鱼页 → 假冒初始访问跳板
- OPSEC：抢注动作在云厂商侧有实名/账单痕迹，演习环境按 RoE 评估是否适用
- 与打点清单联动：asset-triage 指纹出 OSS/COS/S3 域名的资产，进 W1 直接过一遍 §2 引用源
